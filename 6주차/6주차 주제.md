1. #### 블록 단위 암호화

   1. 개념

      1. 긴 데이터를 고정된 크기의 블록으로 나눈 뒤, 각 블록을 암호화하는 방식
   2. 필요 이유

      1. 현실 데이터는 길이가 다양 -> 암호 알고리즘이 처리하기 쉬운 단위가 필요
   3. 실제 활용 예시

      1. 파일 암호화
      2. 디스크 암호화
      3. HTTPS 내부 데이터 보호
      4. AES 사용 사례
2. #### ECB·CBC·CTR

   1. 개념

      1. 블록들을 어떤 규칙으로 암호화할지 정하는 운영 모드
   2. ECB : 각 블록을 독립적으로 암호화

      1. 장점 : 구조가 단순
      2. 단점 : 같은 평문 블록 = 같은 암호문 블록
   3. CBC : 이전 암호문 블록을 다음 평문 블록에 섞어서 암호화

      1. 핵심 : 블록들이 서로 연결
   4. CTR : 카운터 값을 암호화해서 만든 값을 평문과 XOR

      1. 핵심 : 카운터 블록 재사용 금지
3. #### IV의 필요성

   1. IV

      1. 같은 키와 같은 평문을 사용해도 암호화 결과가 반복되지 않게 하기 위한 시작값
   2. 필요 이유

      1. 같은 평문을 같은 키로 암호화하여 항상 같은 암호문이 도출 -> 평문 추측 가능
      2. IV를 사용하여 반복을 막고 암호화 결과를 매번 다르게 만듦
