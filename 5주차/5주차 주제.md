1. #### 대칭키 암호

   1. 개념

      1. 암호화할 때 쓰는 키와 복호화할 때 쓰는 키가 같은 암호 방식
   2. 필요 이유

      1. 빠르게 많은 데이터를 보호할 수 있기 때문
   3. 특징

      1. 알고리즘이 공개되어도 키가 안전하면 내용을 보호할 수 있어야 함
      2. 대칭키 암호는 양쪽이 같은 키를 써야 함 -> 그 키를 어떻게 안전하게 공유할 것인가가 매우 중요
   4. 실제 활용 예시

      1. 파일 암호화
      2. 디스크 암호화
      3. HTTPS 통신 내부의 데이터 보호
      4. AES 사용 사례
   5. 이전 개념과의 연결

      1. 2주차 : 카이사르 암호, 단순 치환 암호

         1. 고전적인 대칭키 암호라고 볼 수 있음
      2. 3주차 : 브루트포스, 키 공간 개념

         1. 대칭키 암호가 안전하려면 가능한 키 후보가 적으면 안 됨
      3. 4주차 : 암호화, 해시

         1. 대칭키 암호 : 복호화가 필요한 암호화에 해당
2. #### 대칭키 암호의 암·복호화

   1. 개념

      1. 같은 비밀키를 사용해 평문을 암호문으로 바꾸고, 다시 암호문을 평문으로 되돌리는 과정
   2. 필요 이유

      1. 기밀성 제공

         1. 허가되지 않은 사람이 암호문을 봐도 원래 내용을 알기 어렵게 함
      2. 데이터 재사용 가능

         1. 파일, 메시지, 디스크 데이터처럼 나중에 다시 읽어야 하는 정보는 복호화가 가능해야 함
      3. 올바른 키의 중요성 확인

         1. 같은 알고리즘을 사용해도 키가 다르면 원래 평문으로 돌아오지 않음
3. #### 대칭키 암호의 속도와 키 공유

   1. 개념

      1. 빠르게 많은 데이터를 암호화할 수 있다는 장점
      2. 같은 키를 안전하게 공유해야 한다는 문제
   2. 필요 이유

      1. 대칭키 암호의 장점과 한계를 동시에 이해 가능

         1. 속도가 빠르다는 의미

            1. 단순히 실행 시간이 짧다는 뜻만이 아님
            2. 같은 시간 안에 더 많은 데이터를 암호화/복호화 가능
         2. 키 공유가 어렵다는 의미

            1. 키를 아는 사람 = 암호문을 풀 수 있는 사람
            2. => 키 관리 방법의 문제
