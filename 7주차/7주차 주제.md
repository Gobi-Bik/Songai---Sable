1. #### 키 분배 문제

   1. **개념**

      1. 암호화에 사용할 비밀키를 상대방에게 어떻게 안전하게 전달할 것인가의 문제
   2. **필요 이유**

      1. 키를 아는 사람 = 암호문을 풀 수 있는 사람
      2. 키 전달 관점이 뚫리면 알고리즘이 아무리 강해도 의미 X
2. #### 공개키 / 대칭키란?

   1. **공개 키**

      1. **개념**

         1. 공개키와 개인키라는 서로 다른 두 키를 사용하는 방식
      2. **사용 방향**

         1. 암호화/키 전달

            1. 공개키로 어떤 값을 보호하고, 개인키를 가진 사람만 풀 수 있게 만들 수 있음
         2. 전자서명/인증

            1. 개인키로 서명하고, 공개키로 그 서명이 맞는 검증 가능
   2. **대칭 키**

      1. **개념**

         1. 암호화할 때 쓰는 키와 복호화할 때 쓰는 키가 같은 방식
      2. **장점**

         1. 빠름
      3. **단점**

         1. 키 공유가 어려움
3. #### 공개키 / 대칭키의 역할

   * 실제 시스템에서는 둘을 혼용
   1. **핵심 역할 분담**

      1. **구분					공개키 암호					대칭키 암호**
      2. 키 구조				공개키 + 개인키					하나의 비밀키
      3. 속도					상대적으로 느림					빠름
      4. 주된 역할				키 교환, 인증, 전자서명				실제 데이터 암호화
      5. 장점					안전한 시작, 신원 확인				대량 데이터 처리
      6. 단점					대량 데이터 암호화에는 비효율적		키 분배가 어려움
   2. **요약**

      1. 공개키 : 처음 안전하게 연결을 시작하는 역할
      2. 대칭키 : 연결 이후 실제 데이터를 빠르게 암호화하는 역할
   3. **실제 예시**

      1. HTTPS / TLS
      2. 메신저 보안 통신
      3. 파일 공유 암호화
      4. 전자서명
   4. **이전 주차와의 연결**

      1. 5주차 : 대칭키 암호는 빠르지만 같은 키를 공유해야 함
      2. 이번 주차 : 그 키를 어떻게 안전하게 나눌 것인가?
      3. => 공개키 암호와 혼합 구조로 이어짐
